# Использование модуля оценки производительности

Роль `tracing` предназначена для выполнения трассировки пользовательских функций.

Перед работой с примером рекомендуется изучить следующие ссылки:

- подробнее про роль `tracing` можно прочитать [здесь](../../TRACING.md);
- подробности по работе с кластером через Docker Compose можно найти [здесь](../up_with_docker_compose/README.md);
- также в данном примере используется сторонний сервис для сбора данных трассировки Jaeger, подробности можно найти
  на [официальном сайте](https://www.jaegertracing.io/).

## Описание конфигурации

В данном примере указаны следующие параметры:

```yaml
tracing:
  enabled: true
  global_sample_rate: 0
  sample_rates:
    get_token_router: 2
    debug_1: 1
```

Это означает, что по умолчанию сегменты (span) трассировки не будут засекать время выполнения участков кода.
Время выполнения участков кода будет засекаться, если выполнено одно из следующих условий:

- в контексте будет указан параметр `sample: true`;
- название родительского сегмента трассировки будет `get_token_router` или `debug_1`, при этом вероятность
  замера времени для нового сегмента будет равна 1/N (1/2 и 1 соответственно).

Также в данном примере указаны следующие параметры:

```yaml
tracing:
  base_url: 'http://tracing:9411/api/v2/spans'
  api_method: 'POST'
  report_interval: 1
  spans_limit: 1000
```

Они отвечают за отправку результатов трассировки в сторонний сервис Jaeger.

## Пример использования

1. Запустим пример:

   ```shell
   docker compose up -d
   ```

2. Подключимся через `tt` к роутеру:

   ```shell
   tt connect admin:secret-cluster-cookie@localhost:3300
   ```

3. Запустим несколько тестовых функций на роутере:

   ```lua
   for i = 1, 10 do
       box.func.get_token:call({"test"})
   end
   box.func.debug_func:call({"debug_1"})
   box.func.debug_func:call({"debug_2"})
   ```

4. Зайдем в веб-интерфейс Jaeger на http://127.0.0.1:16686,
   в поле `Service` выбираем `default@tarantool-router:3301`, далее нажимаем `Find Traces`.
   В результате увидим примерно 5 результатов трассировки для функции `get_token`
   и ровно 1 результат для функции `debug_func` с сегментом `debug_1`.

   ![Результаты трассировки](./images/tracing_results.jpg)

5. Если открыть результат трассировки для функции `get_token`, то можно увидеть, что функция `get_token`
   выполняется примерно за 12 мс. Из них 10 мс тратится на выполнение функции на экземпляре `storage`.
   Еще по 1 мс тратится на коммуникацию экземпляров по сети до и после вызова функции на экземпляре `storage`.
   Отсюда можно сделать вывод, что 80% времени выполняется логика на экземпляре `storage`
   и следует начать оптимизацию кода оттуда.

   ![Результат трассировки функции get_token](./images/tracing_get_token.jpg)

6. Остановим пример:

   ```shell
   docker compose down
   ```
