# Выполнение миграций с удалённой машины

Пример показывает выполнение миграций с отдельного хоста, не входящего в состав кластера. Для примера потребуется
запущенный и сконфигурированный кластер, готовый к работе. В качестве кластера будут высттупать узлы, запущенные
в docker compose. В данном примере нам не важно как запущен кластер - всё справедливо и для кластера, запущенного
и сконфигурированного с помощью Ansible Cartridge Enterprise или запущенного локально.

Для этого примера понадобятся:
* Docker-образ TarantoolDB ([установить](../../INSTALL.md))
* Docker compose

## Подготовка стенда
Для запуска кластера из директории ``migrations_from_remote_host`` выполните:
``` shell
docker compose up -d --build
```

Проверьте, что кластер успешно запустился, для этого выполните команду:
```shell
docker compose logs installer
```

Последняя строка должна быть такой:
```
Cluster started
```

Для первоначального конфигурирования кластера были использованы следующие файлы:
* [docker-compose.yml](./docker-compose.yml) - для описания узлов кластера.
* [bootstrap/topology.json](./bootstrap/topology.json) - для описания топологии кластера

В итоге мы запустили стенд, состоящий из:
* простого кластера TarantoolDB на два роутера и два шарда
* веб-сервера NGINX, предоставляющего доступ к серверу "снаружи" по HTTP с авторизацией и балансировкой нагрузки

Теперь доступ к админ-функциям кластера "извне" предоставляется по адресу: http://localhost:8000. Но также можно
заходить в админки узлов кластера "изнутри", например по адресу: http://localhost:8081.

Для выполнения примера нам также понадобится скрипт, выполняющий миграции. Его можно скопировать из папки с 
утилитами:
```shell
cp ../../../client/utils/migrate.sh ./
chmod a+x migrate.sh
```

## Авторизация
В качестве примера для доступа "снаружи" используется авторизация по токену. В запросе должен присутствовать
заголовок:
```
Authorization: Bearer 123
```

Логика проверки данного заголовка настроена в конфигурации NGINX.

## Запуск миграции
Выполняется командой:
```shell
TARANTOOLDB_TARGET_URI=localhost:8000 TARANTOOLDB_BOOTSTRAP_PATH=./user-host/ TARANTOOLDB_HEADERS="Authorization: Bearer 123" ./migrate.sh
```

По завершению в консоли появляется такой вывод:
```
Load config..
Config loaded
Start migrate..
Migrations completed successfully
```

Через админку можно убедиться в успешном выполнении миграций - загружена конфигурация кластера
и созданы спейсы `test1` и `test2`.

Для выполнения данной операции были использованы следующие файлы:
- [bootstrap/config.yml](./bootstrap/config.yml) - в качестве конфигурации кластера
- [bootstrap/migrations/source](./bootstrap/migrations/source/) - описание миграций
- скрипт [`migrate.sh`](../../../client/utils/migrate.sh) из [набора клиентских утилит](../../../client/utils/) -
  для загрузки конфигурации кластера, клиентского кода и выполнения миграций.
  Описание скрипта см. [здесь](../../../client/utils/migrate.md).

## Останов стенда
Останов стенда производится командой:
```shell
docker compose down
```
