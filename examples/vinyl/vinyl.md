# Использование vinyl-спейсов

В этом руководстве описано, как настроить и использовать `vinyl`-спейсы.   

`Vinyl` - это движок хранения Tarantool, предназначенный для работы с большими объёмами данных, превышающими доступный объём оперативной памяти. В отличие от `memtx`, который хранит данные в RAM, `vinyl` хранит данные на диске, используя LSM-деревья (Log-Structured Merge Tree).

## Пререквизиты

Для выполнения примера вам понадобится:

* Установленный Docker-образ Tarantool DB;
* Приложение Docker Compose;
* Утилита tt CLI;
* Исходные файлы примера `vinyl`.

## Запуск кластера

Для успешного запуска кластера должны быть свободны следующие порты: 

* 2379
* 3300--3308
* 8081

Перейдите в папку с примером `vinyl`:

```shell
cd ./doc/examples/vinyl/
```

Запустите кластер:

```shell
make start
```

После выполнения команды будет развернут следующий стенд:
- Кластер Tarantool DB:
  - 2 роутера
  - 2 набора реплик по 3 хранилища
- Кластер etcd из 3 узлов
- Tarantool Cluster Manager (TCM)

После запуска должны работать все контейнеры, кроме `init_host`, который используется только для инициализации и завершает свою работу после настройки кластера.

## Доступ к Tarantool Cluster Manager

После запуска кластера становится доступен веб-интерфейс Tarantool Cluster Manager (TCM).
Откройте в браузере адрес http://localhost:8081.
Для входа используйте следующие логин и пароль:
- **Username**: `admin`
- **Password**: `secret`

Через TCM вы можете управлять кластером и подключаться к узлам.

## Создание vinyl-спейса

В данном руководстве используется миграция, определённая в файле: `./cluster/migrations/scenario/001_messages.lua`.

В этом файле создаётся шардированный `vinyl`-спейс `messages`, предназначенный для хранения пользовательских сообщений.

### Составной первичный индекс

Спейс `messages` использует составной первичный индекс по двум полям:
- `bucket_id` -- идентификатор виртуального сегмента, используемый для шардирования
- `id` -- идентификатор сообщения

Создание отдельного вторичного индекса по `bucket_id` было бы избыточным и неэффективным при использовании `vinyl`:
- Каждый вторичный индекс в `vinyl` представляет собой отдельное LSM-дерево, которое требует дополнительного места на диске.
- При поиске по вторичному индексу Tarantool сначала находит первичный ключ во вторичном индексе, а затем обращается к первичному индексу, чтобы получить полную запись. При выполнении range-запроса это приводит к случайным чтениям с диска.

Используя составной первичный индекс `{ bucket_id, id }`, мы получаем возможность шардирования без издержек вторичного индекса.

### Регистрация ключа шардирования

Модуль `CRUD` по умолчанию вычисляет `bucket_id` по первичному ключу, поэтому в миграции необходимо явно указать `id` в качестве ключа шардирования:

```lua
helpers.register_sharding_key('messages', { 'id' })
```

## Работа с данными через модуль CRUD

Чтобы начать работу с базой данных через интерактивную консоль Tarantool, нужно подключиться к узлу кластера. Это можно сделать двумя способами:

- Через веб-интерфейс TCM;
- Через терминал с помощью утилиты tt CLI:

  ```shell
  tt connect admin:secret-cluster-cookie@localhost:3301
  ```

Подключитесь к роутеру `router-msk`, используя **первый способ** -- через TCM. Для этого:

1. Перейдите в раздел **Stateboard**.
2. Нажмите на набор реплик `router-msk`.
3. Выберите узел `router-msk` и в открывшемся окне перейдите на вкладку **Terminal**.

Теперь вы находитесь в интерактивной консоли Tarantool и можете выполнять запросы к кластеру.

### Определение вспомогательных функций

Для удобства ввода данных добавьте в консоль две вспомогательные функции.

Функция `now()` возвращает текущее время: 

```lua
function now()
    local datetime = require('datetime')
    return datetime.now()
end
```

Функция `get_pk(id)` формирует первичный ключ в виде `{ bucket_id, id }`, вычисляя `bucket_id`:

```lua
function get_pk(id)
    return { vshard.router.bucket_id_strcrc32(id), id }
end
```

### Вставка данных

Добавим несколько сообщений в спейс `messages` с помощью `crud.insert_object_many`:

```lua
crud.insert_object_many('messages', {
    { id = 1, text = 'Привет!', created_at = now() },
    { id = 2, text = 'Hello world', created_at = now() },
    { id = 3, text = 'Bye', created_at = now() },
    { id = 4, text = 'Ok', created_at = now() },
    { id = 5, text = 'Hi', created_at = now() },
})
```

### Выборка данных

Посмотрим содержимое спейса с помощью операции `crud.select()`:

```lua
crud.select('messages')
```

Пример вывода:

```yaml

  - [3, 11804, 'Bye', '2025-08-28T11:12:09.028313Z']
  - [5, 1172, 'Hi', '2025-08-28T11:12:09.028333Z']
  - [2, 21401, 'Hello world', '2025-08-28T11:12:09.028312Z']
  - [4, 28161, 'Ok', '2025-08-28T11:12:09.028330Z']

    {'name': 'text', 'type': 'string'}, {'name': 'created_at', 'type': 'datetime'}]
```

### Получение одной записи

Прочитаем запись с `id = 1`:

```lua
crud.get('messages', get_pk(1))
```

Вывод:

```shell
---
- rows:
  - [1, 12477, 'Привет!', '2025-08-28T11:12:09.028308Z']
  metadata: [{'name': 'id', 'type': 'number'}, {'name': 'bucket_id', 'type': 'unsigned'},
    {'name': 'text', 'type': 'string'}, {'name': 'created_at', 'type': 'datetime'}]
- null
...
```

### Обновление записи

Обновим сообщение с `id = 2`, изменив его текст:

```lua
crud.update('messages', get_pk(2), { {'=', 'text', 'Some text'} })
```

Вывод:

```shell
---
- rows:
  - [2, 21401, 'Some text', '2025-08-28T11:12:09.028312Z']
  metadata: [{'name': 'id', 'type': 'number'}, {'name': 'bucket_id', 'type': 'unsigned'},
    {'name': 'text', 'type': 'string'}, {'name': 'created_at', 'type': 'datetime'}]
- null
...
```

### Удаление записи

Удалим сообщение с `id = 1`:

```lua
crud.delete('messages', get_pk(1))
```

Вывод:

```shell
---
- rows: []
  metadata: [{'name': 'id', 'type': 'number'}, {'name': 'bucket_id', 'type': 'unsigned'},
    {'name': 'text', 'type': 'string'}, {'name': 'created_at', 'type': 'datetime'}]
- null
...
```

Обратите внимание: операция `delete` в `vinyl` не возвращает удалённый кортеж.

## Особенности работы с vinyl

При работе с `vinyl` необходимо учитывать следующие особенности, отличающие его от `memtx`: 

1) Функция `len()` возвращает только приблизительное количество кортежей в спейсе. Если необходимо точное количество, используйте `count()` или `pairs():length()`, но имейте в виду, что эти операции значительно медленнее.

2) Операция `delete` не возвращает удалённый кортеж. Если нужно значение кортежа, выполните `get` перед `delete`.

3) Возможно переключение контекста файбером при чтении из `vinyl`, поскольку данные могут отсутствовать в памяти и придется обращаться к диску.

Подробнее о различиях между `vinyl` и `memtx` можно узнать в официальной документации:  

https://www.tarantool.io/en/doc/latest/platform/engines/memtx_vinyl_diff/

## Параметры vinyl

Для настройки производительности `vinyl`-индексов доступны следующие параметры: 

* `bloom_fpr` - коэффициент ложноположительного срабатывания фильтра Блума (по умолчанию 0.05). Чем ниже значение, тем точнее фильтр, но больше потребление памяти.
* `page_size` - размер страницы при чтении и записи (в байтах, по умолчанию 8192).
* `range_size` - максимальный размер диапазона по умолчанию (в байтах)
* `run_count_per_level` - максимальное количество файлов (забегов) на каждом уровне LSM-дерева (по умолчанию 2). Чем больше значение, тем шире LSM-дерево.
* `run_size_ratio` - соотношение между размерами уровней в LSM-дереве (по умолчанию 3.5). Чем меньше значение, тем выше LSM-дерево.
